## Not accepted yet

- P0 remains blocked for formal historical execution pending timestamp semantics, point-in-time status/calendar evidence, the uncovered early-2023 rule interval, and complete official corporate-action accounting. The 49-label clock grid is verified but does not prove interval meaning or that endpoints are executable. The 74 early-history daily missing rows do not overlap the planned 2023–2024 development window.
- The exact Moutai status rows exist, but their historical availability cannot be proven; status files also lack complete listing/delisting lifecycle evidence. The calendar is now mapped for 2022–2026, but its exact date match does not upgrade retrospective status rows to PIT evidence.
- The existing A-share `quant_v2` integration has a configured private `.env`. JevQuant references that file locally through its ignored `.env`; it reads the key in memory without copying or printing it. The live smoke call used synthetic state only and did not place an order.
- Formal P4 acceptance remains pending: local minute labels have no provider evidence proving whether they mark interval ends; actual publication delay is unknown; status data are retrospective, and 2023 rule evidence starts only on 2023-04-10. The new diagnostic runner records these assumptions explicitly so these complete account runs cannot be mistaken for verified execution history.
- P6's completed calls replay historical inputs; no genuine forward session was run. The open final position remains valued, not forcibly liquidated. All P4/P6 real-price results are diagnostic until timestamp semantics, status availability, rule dates and complete action coverage are proven.
- The 20-session P6 diagnostic produced no position because all 3 model BUY recommendations were rejected by the configured execution proxy. This is an execution result, not a claim that JEV never emits BUY. Do not relax the OHLC/slippage guard simply to force a fill; first inspect whether this proxy is an appropriate execution assumption for a future study.
- The full-account P6 prompt comparison is completed for this short sample, but it does not establish which prompt should be adopted. JEV output contains probabilities and confidence, not per-decision rationale, and the state diverges after the first buy. Any selected prompt must be frozen as a new experiment version and evaluated over broader, predeclared data.
- No historical strategy comparison, forward simulation, or profitability claim has been made.

## API usage policy

There is no request-count or spend hard cap, and no automatic shutdown based on cost. Each real response records requested/resolved model, input/output tokens and estimated cost when returned by the provider. Repeating an identical validated request reuses the local cache. Cache and usage records are local run artifacts and are Git-ignored.

For an existing private key file, set `JEVQUANT_TYPESAFE_ENV_FILE` to its path in the local process environment. JevQuant reads only the `TYPESAFE_API_KEY` entry; it does not copy the file, print the key, or include the path in public project files.
