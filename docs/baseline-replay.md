# Non-JEV baseline replay

`baseline_replay.py` runs each policy in a fresh CNY 1,000,000 account. It uses the same fee schedule, reserve, T+1 lots, price protection, execution delay, adverse open proxy, limit/suspension checks, 20-session same-slot liquidity cap, and event-based independent reconciliation for every policy.

The replay accepts normalized `Bar` events only when each bar has explicit `interval_start`, `interval_end`, and `available_at`, with the record available no earlier than interval completion. The caller must supply an independently sourced schedule of eligible interval starts, session close times, next trade dates, per-date suspension and price-limit rules, and a point-in-time buy-eligibility flag. Missing eligibility defaults to false. The raw user Parquet files are read-accessible, but their `trade_time` labels are not normalized to intervals because the local collection has no verified provider convention; those bars cannot yet enter this replay.

At each completed bar the policy receives only prior completed daily closes and current account state. For an order, the replay applies the five-minute delay, selects the next schedule start, freezes the median volume of that slot from the preceding 20 sessions, floors the 1% cap to the lot size, and submits no more than that cap. A sell intent targets all T+1-sellable shares, while each order is capped to the same liquidity rule; any residual position remains open and is reconsidered at the next decision. It does not move an order to another slot if the expected interval is absent. Buy and sell orders are released at session end. Any held position with no mark through the declared close makes the run `ACCOUNT_REPLAY_INCOMPLETE_VALUATION` even if the cash/share reconciliation passes.

`iter_baseline_suite()` yields independent accounts for `CASH`, `BH80`, `BH50`, `BH_MAX`, `MA5_20`, and one `RANDOM` account per supplied seed (default 0–99). `summarize_baseline_result()` reports terminal return, daily marked drawdown, filled trade count, costs, exposure, and reconciliation state. It is suitable for offline, no-JEV comparisons; it does not call the provider.

The test fixtures use synthetic 15-minute sessions with explicit intervals and are engineering checks only. No historical baseline account or strategy-performance report has been generated from the real Moutai data yet.
