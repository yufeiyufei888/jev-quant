# Non-JEV baseline replay

`baseline_replay.py` runs each policy in a fresh CNY 1,000,000 account. It uses the same fee schedule, reserve, T+1 lots, price protection, execution delay, adverse open proxy, limit/suspension checks, 20-session same-slot liquidity cap, and event-based independent reconciliation for every policy.

The replay accepts normalized `Bar` events only when each bar has explicit `interval_start`, `interval_end`, and `available_at`, with the record available no earlier than interval completion. The caller supplies a schedule of all bar starts separately from eligible order-arrival starts, session close times, next trade dates, per-date suspension and price-limit rules, and a buy-eligibility flag. Missing eligibility defaults to false. The local Parquet files are readable and complete for the audited dates, but their `trade_time` labels have no embedded provider convention proving interval meaning.

At each completed bar the policy receives only prior completed daily closes and current account state. For an order, the replay applies the five-minute delay, selects the next schedule start, freezes the median volume of that slot from the preceding 20 sessions, floors the 1% cap to the lot size, and submits no more than that cap. A sell intent targets all T+1-sellable shares, while each order is capped to the same liquidity rule; any residual position remains open and is reconsidered at the next decision. It does not move an order to another slot if the expected interval is absent. Buy and sell orders are released at session end. Any held position with no mark through the declared close makes the run `ACCOUNT_REPLAY_INCOMPLETE_VALUATION` even if the cash/share reconciliation passes.

`iter_baseline_suite()` yields independent accounts for `CASH`, `BH80`, `BH50`, `BH_MAX`, `MA5_20`, and one `RANDOM` account per supplied seed (default 0–99). `summarize_baseline_result()` reports terminal return, daily marked drawdown, filled trade count, costs, exposure, and reconciliation state. It is suitable for offline, no-JEV comparisons; it does not call the provider.

`retrospective_replay.py` provides a deliberately separate diagnostic path for the supplied Moutai Parquet files. It tests the explicit hypothesis that each standard label is an interval end (`label - 5 minutes` through `label`), excludes the separate 09:30 record, and assumes availability at interval end. Execution starts are restricted to 09:35–11:25 and 13:05–14:50. It also uses retrospective status files. The runner requires an explicit command-line acknowledgment and stamps every output `DIAGNOSTIC_ONLY_NOT_FORMAL_HISTORICAL_EXECUTION_ACCEPTANCE`; it must not be used to claim verified historical fills or select a winning strategy.

The 20-session smoke scenario and full 484-session 2023–2024 development scenario each ran 105 separate accounts from the local files. Account reconciliation and daily valuation completeness passed for all 105 in both runs. Detailed raw run artifacts stay under the ignored local `artifacts/` directory. The synthetic tests remain engineering checks; the real-data runs are assumption-bound diagnostics, not formal baseline acceptance.
